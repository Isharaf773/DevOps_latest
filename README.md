# Food Delivery - Full DevOps Project

MERN food-delivery app (customer site, admin panel, REST API, MongoDB) with a complete
DevOps toolchain: **Docker -> Jenkins CI/CD -> Terraform (AWS)**.

```
 developer --git push--> Jenkins ──► quality gates (syntax, lint, terraform validate)
                            │         build images ► Trivy scan ► push to Docker Hub
                            │         terraform plan/apply (AWS)  ► deploy ► smoke tests
                            ▼
        ┌──────────────── AWS EC2 (Terraform: VPC, subnet, SG, EIP, key pair) ───────────────┐
        │  docker compose                                                                    │
        │   frontend (nginx :3000) ─┐                                                        │
        │   admin    (nginx :3001) ─┼──► backend (Node/Express :4000) ──► MongoDB (internal) │
        └────────────────────────────────────────────────────────────────────────────────────┘
```

## Repository layout

| Path | What it is |
|------|-----------|
| `backend/` | Express API (config from env vars, `/health` endpoint, non-root image) |
| `frontend/`, `admin/` | React + Vite apps built into nginx images; API URL is injected **at container start** (`API_URL`), so one image runs anywhere |
| `docker-compose.yml` | Production-style stack (MongoDB, backend, frontend, admin) |
| `docker-compose.dev.yml` | Hot-reload development stack |
| `docker-compose.jenkins.yml`, `jenkins/` | Jenkins image with Docker CLI, Compose and Terraform |
| `Jenkinsfile` | The pipeline |
| `terraform/aws/` | Real infrastructure: VPC + EC2 + Elastic IP, bootstraps Docker and the app |
| `terraform/local/` | Same stack on your own Docker Desktop through the Docker provider |
| `.env.example` | All configuration variables |
| `docs/` | `JENKINS.md`, `TERRAFORM.md`, `archive/` (old notes) |

## 1. Run it locally (Docker only)

```bash
sh start.sh          # Windows: start.bat   (creates .env with random secrets on first run)
```

| Service | URL |
|---------|-----|
| Customer site | http://localhost:3000 |
| Admin panel | http://localhost:3001 |
| API health | http://localhost:4000/health |

Other modes: `sh start.sh dev` (hot reload), `sh start.sh down` (stop).
Plain compose works too: `cp .env.example .env && docker compose up -d --build`.

## 2. Jenkins CI/CD

See [docs/JENKINS.md](docs/JENKINS.md). Short version:

```bash
docker compose -f docker-compose.jenkins.yml up -d --build
docker exec food_jenkins cat /var/jenkins_home/secrets/initialAdminPassword   # then open http://localhost:8080
```

## 3. Deploy to AWS with Terraform

See [docs/TERRAFORM.md](docs/TERRAFORM.md).

```bash
cd terraform/aws
cp terraform.tfvars.example terraform.tfvars   # edit it
terraform init && terraform apply
```

## Configuration

Everything comes from environment variables (see `.env.example`). `.env` is git-ignored.
Mongo password / JWT secret are generated by `start.sh` locally and by Terraform on AWS.

## Security notes

- No credentials are stored in the code any more. The old `backend/config/db.js` and
  `user_data.sh` contained a MongoDB Atlas username and password - **rotate that password in Atlas**
  and remove it from git history if the repo was ever pushed.
- MongoDB is bound to `127.0.0.1` locally and is not opened in the AWS security group.
- SSH on AWS is limited to the CIDRs you list in `allowed_ssh_cidrs`.
- The backend container runs as the non-root `node` user.
- The Jenkins container mounts the host Docker socket (root-equivalent). Fine for a lab, not for a shared server.
