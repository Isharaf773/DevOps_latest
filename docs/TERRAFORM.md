# Terraform

Two independent configurations:

| Folder | Creates | Needs |
|--------|---------|-------|
| `terraform/aws` | VPC, public subnet, internet gateway, route table, security group, key pair, Elastic IP, Ubuntu 22.04 EC2 (Docker + app bootstrapped by `user_data`) | AWS account + credentials, Docker Hub images (or it builds on the server) |
| `terraform/local` | Network, volumes and 4 containers on your own Docker Desktop | Terraform + built images (`docker compose build`) |

## AWS

```bash
export AWS_ACCESS_KEY_ID=...        # PowerShell: $env:AWS_ACCESS_KEY_ID="..."
export AWS_SECRET_ACCESS_KEY=...
cd terraform/aws
cp terraform.tfvars.example terraform.tfvars    # set allowed_ssh_cidrs, repo_url, image_namespace
terraform init
terraform plan
terraform apply
```

Outputs give the Elastic IP, the three URLs and the SSH command. First boot takes ~3-5 minutes;
watch it with `ssh ubuntu@<ip> tail -f /var/log/food-bootstrap.log`.

What happens on the server: Docker is installed, the repo is cloned to `~/food-delivery`, a `.env` is written
(random Mongo password and JWT secret generated by Terraform, `API_URL` set to the Elastic IP), images are
pulled from Docker Hub (or built locally if they are not there yet) and `docker compose up -d` runs.

Notes
- Costs: a `t3.small` + Elastic IP + 20 GB gp3 is a few dollars per month. Run `terraform destroy` when done.
- Secrets end up in Terraform state and EC2 user-data. Keep state private (use the S3 backend below);
  for production move them to SSM Parameter Store.
- Remote state: rename `backend.tf.example` to `backend.tf` after creating the bucket + lock table
  (commands are inside the file), then `terraform init -migrate-state`.
- Commit `.terraform.lock.hcl` (created by `init`); never commit `terraform.tfvars` or `*.tfstate`.

## Local (Docker provider)

```bash
docker compose build                      # creates foodapp/backend|frontend|admin:latest
cd terraform/local
cp terraform.tfvars.example terraform.tfvars
terraform init && terraform apply
```

Uses different container/volume names (`food_tf_*`), but the same host ports as the compose stack, so stop one
before starting the other. On Linux/macOS set `docker_host = "unix:///var/run/docker.sock"`.
